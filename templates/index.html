01 — Balance Model

Spherical Inverted Pendulum

Rather than driving the torso with separate hip/waist joint angles, TerraWalk AI treats the pelvis as a single spherical inverted pendulum. Every command resolves to one unit quaternion instead of stacked Euler angles, which avoids gimbal lock entirely, even during extreme combined pitch-and-roll maneuvers like a sidestep on a steep cross-slope.

Negative pitch leans the torso forward for running, climbing, or accelerating; positive pitch leans it back for braking or standing up out of a crouch. Roll is driven almost entirely by sidestepping. A dedicated client-side system also continuously measures the real ground slope under the feet and blends its own compensating lean in on top of this — see Torque & Terrain below.

02 — Ground Stability

Zero-Moment Point & Capture Point

The Zero-Moment Point is the ground point where the net reaction force from the feet must act for the robot to stay upright without toppling. TerraWalk AI receives a bounded capture-point target with each accepted command and interpolates the pulsing red marker toward that location on the terrain. The fixed green ring marks the terrain origin.

The forward/backward component can project further ahead as velocity increases, while the lateral component shifts for sidesteps. The current 0-100% HUD value is a client-side motion/stumble estimate; automatic falls remain governed by measured terrain tilt, unsupported drops, explicit fall commands, and map-boundary support loss.

03 — Gait Physics

Linear Inverted Pendulum Model

Rather than trusting the Kinematic Brain's raw velocity output directly, the client derives a natural angular frequency (ω = √(g / pendulum height)) from this rig's leg length and uses it to bound stride length against cadence. Walking and running speed can never exceed max step length × max step frequency, which is what keeps the gait physically grounded across every terrain biome instead of snapping to an unrealistic pace.

04 — Actuation & Terrain Response

Torque Telemetry & Slope Recovery

Every command becomes a bounded actuation plan, every local grade becomes a measured response, and only supported authored descents convert a dangerous face into a controlled slide.

Schema Evolution

Changing JSON without disconnecting the robot

A format change is a coordinated contract change: schema, sanitizer, response version, and browser consumer move together.

Current // v3.2

Version and provenance

Every successful browser-issued response identifies its schema, controlling source, and echoed request correlation. Provider warnings are additive metadata, so fallback operation remains transparent to the UI.

Add fields defensively

Optional telemetry can be added without breaking older consumers when the browser supplies defaults and ignores fields it does not yet understand.

Recommended migration // major

Add a version gate before v4

The current v3.2 browser correlates requests but does not yet reject schema majors. Before renaming or removing a required field, add a version-aware decoder or explicit guard, then advance the major version.

schema 4.x → version-aware decoder future guard: reject unsupported major before state mutation

Connection Lifecycle

How the browser stays synchronized

The frontend does not hold a persistent movement session on the server. Each command is a complete, stateless snapshot; continuity remains in the browser's simulation state and revision counters.

  1. Capture. The interface records command text plus terrain, friction, incline, and the currently blocking hazard.
  2. Bound the wait. A 25-second AbortController timeout prevents a stalled provider call from freezing the controls.
  3. Validate twice. Groq uses a strict JSON schema; the backend sanitizer then clips numbers, repairs enums, and canonicalizes the pelvic quaternion.
  4. Degrade safely. Provider errors route through a deterministic traversal controller with the same response contract.
  5. Apply atomically. Only a correlated, non-stale response mutates gait, heading, obstacle action, capture target, and fall state; torque estimates are displayed as bounded telemetry.
